Context-Aware Multi-Turn Prompt Injection Detector

github ↗

Capstone research project testing whether analyzing a full conversation — not just the latest message — improves detection of multi-turn prompt injection attacks against LLM applications. Built a rule-based detector that scores instruction overrides, role manipulation, and context-poisoning patterns across turns, then validated it against a static single-prompt baseline.

  • Reached perfect precision and recall on blind held-out and external validation sets, versus roughly 80% accuracy for the single-prompt baseline
  • Held a 0% false-positive rate on a benign cybersecurity/AI-safety stress set, so legitimate security discussion wasn't flagged
  • Fully reproducible: frozen detector hashes, dataset validation, and statistical significance testing (Wilson intervals, McNemar's test)

Local LLM Safety Evaluation & Mitigation

team project · Fall 2025

Course project with a teammate evaluating the safety robustness of a locally-deployed, offline LLM (Mistral-7B-Instruct via GPT4All). We built a threat model around three failure modes — narrative/roleplay jailbreaks, session memory leakage, and instruction-order brittleness — then designed, implemented, and re-tested targeted mitigations for each. All testing used fully synthetic data in a sandboxed, offline environment, with results reported only to our instructor as part of a responsible-disclosure approach.

  • Found jailbreak success was driven almost entirely by narrative framing: professional or fictional framing hit up to 100% attack success, while direct requests were reliably refused
  • Measured a clear recency bias in instruction-following: unsafe requests placed after safety instructions succeeded 50% of the time, versus 0% when safety instructions came last
  • Designed and prototyped three mitigations — a strengthened system prompt, instruction-order normalization, and session cleanup — which cut unsafe outputs from 70% to 20% and then to 0% once combined
